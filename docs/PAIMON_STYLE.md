# 旅行者语音驱动的派蒙表达增强

日期：2026-11-07。范围：第一阶段的素材整理、接话规则、固定示例及表达对照。动态示例选择尚未实现；不修改知识检索、消息发送、长期记忆或模型调用次数。

## 数据与规则

从男女旅行者资料精确恢复共用引用，抽取 178 条唯一对话，未发现无法识别说话者的候选。32 组经开发助手逐条核对；6 组短节选涵盖善意调侃、感谢、转折、日常、回应关心及体谅。完整原文、行号范围、来源快照、原条目标识均可追溯，见 [素材目录](../knowledge/paimon-style/README.md)。不复制整套角色原始资料到提示。

`config/persona.md` 保持原样，仍规定身份、自然表达及事实边界。新增 `lib/paimon-style.js` 只补充从对话提炼的具体接话习惯，不改称呼、输出协议和是否回应规则；关闭即可精确恢复原提示。这样可以对同一人设作三组对照，也避免改动自定义人设内容。

## 配置与运行

```yaml
persona:
  file: persona.md
  styleMode: off  # off / rules / examples；无效值也回退 off
```

- `off`：原提示。
- `rules`：普通聊天增加接话习惯。
- `examples`：同样的习惯，加 6 组固定短节选。

当前默认 off：本轮实测未显示固定示例有稳定优势，见下方记录。希望小范围试用时优先选择 rules，examples 留作对照选项。首次 JS 更新需重启；之后通过配置切换模式作用于后续请求，在途请求保留原提示。没有独立风格选择 API，不增加工具次数；示例作为独立 user 数据块，与知识资料分别提供，无 kb-/w- ID，不占知识检索槽或引用预算。规则在 system 中明确仅参考表达，不复制剧情事实、用户身份或共同经历，也不续写示例。

`rules` 的额外规则为 257 个 Unicode 码点；`examples` 的额外 system 文本为 425 个码点，示例 JSON 为 1157 个码点（另有短数据标签和换行），构建时对示例 JSON 设置 1500 码点上限。这不是 token 数。主动补话、记忆评估、表情选择及独立面板分析不注入此模块；普通聊天中的攻略仍要求清晰完整、优先事实。不能保证模型完全不受示例内容影响。

## 构建与更新

在插件目录运行 `node scripts/paimon-style.js check` 或 `build`。构建会校验原始旅行者引用，拒绝不明说话者作为样例；审阅条目不存在、重复或节选失效时失败。服务器正常更新生成文件即可，不需要 `knowledge.js build`，角色/剧情原索引不变。

脚本从两份指定旅行者文件读取，不递归混入别的角色。完整男女共用对话按条目标识只保存一份，每个来源保留性别；性别差异保留，不把女版作为玩家默认身份。连续同角色台词合成一次发言，避免将游戏台词分行当成 QQ 连发要求。

## 对照评测

```sh
# 只输出提示快照和计划，不联网
node scripts/eval-paimon-style.js prepare
# 从进程环境变量 DEEPSEEK_API_KEY 读取凭据；不会输出凭据
node scripts/eval-paimon-style.js run --limit=60 --repeats=2
```

三模式使用相同基础人设、模型与参数。60 场景 × 3 模式 × 2 次重复，加上 5 个场景的第二轮，共最多 390 次聊天请求。使用现有 DeepSeekClient，固定当前插件使用的模型 deepseek-flash，temperature=0.8、maxTokens=600、关闭思考、无重试、超时 30 秒。最多 3 个请求并行；同一场景第二轮继承该模式自己的第一轮回复。鉴权、余额、限流、网络错误或累计 5 次异常会停止后续请求，已经发出的请求可能完成或计费。这里的 30 秒是请求级配置，不是整次评测超时。

结果只写入被 Git 忽略的 `data/paimon-style-eval/<时间>/`：manifest、首轮提示快照、响应及 usage、随机打乱模式标签的 blind-review、单独保存的 blind-key、统计摘要。准备/运行使用新目录，不覆盖既有结果。不读取 QQ 日志、用户记忆，不调用搜索、面板或 QQ 发送。

先看 blind-review，再解盲。检查贴合原话、伙伴感、简洁、重复口癖、边界、认真反馈的调整，以及是否虚构事实和共同经历；群聊还检查应否回应。对局部更俏皮和整体更好作区分，允许并列或全部不合格。长度、反问和食物词计数只是筛查线索，不是派蒙相似度评分。由同一开发助手评审也有主观偏差，用户对话体验仍需单独确认。

这套评测只覆盖普通聊天生成，知识类场景提供有限合成资料或缺少证据的情况；它没有运行研究/搜索/面板链，不能证明真实查证准确性或 QQ 沉默行为。已有离线回归检查程序链路。新增 60 场景经本轮观察后成为回归集，不应再称全新留出集。

本地完整离线测试 471/471 通过，新增 5 项风格测试（包括素材可复现、归属与引用、关闭精确回退、数据隔离、模拟多轮评测和错误停止）。提示断言不证明模型遵循。

2026-11-07 完成真实 API 对照：60 场景、3 模式、2 次重复，含 5 组两轮对话，共 390/390 次有效响应，无解析或请求错误。主评测 usage 合计 731,468 tokens，另有 6 次冒烟请求合计 10,692 tokens；网络权限受限时有一次失败尝试，未取得回答或 usage。未将 token 换算为费用。

食物词统计只匹配 `摩拉/好吃/吃的/食物/鸡肉串`，并未判断是否相关，也没有覆盖所有食物词；问号不区分反问和必要澄清。因此不能把这些计数称作坏梗率、准确率或质量提升百分比。

开发助手先在隐藏模式标签的表格中评审第一次重复的全部 65 组回答（三模式共 195 条），将相对选择落盘后才读取映射。并列优选计数分别为 off 35、rules 37、examples 36；唯一优选分别为 8、12、8。4 组全部存在明显问题。这是单个开发助手的主观比较，不是独立用户评测或统计显著性结论；第二次重复未逐条盲评。

可观察到的改善：例如“今天就坐在这里看云吧”，原提示在该次采样转向烤松饼与饥饿，rules 保持平静陪伴；“首席点头官”的玩笑，rules/examples 围绕职位本身接话，off 转向点心。但三种模式总体接近，示例增加输入后未显示稳定收益，且仍常以语气词开头。

共同问题：无根据暗示与用户逛过祭典、能看见用户外观；被指出笑话重复后继续承诺换笑话；将“地图上的路发光”误解为真实道路发光。无日期记录也有被过度说成互相矛盾的回答。仅靠风格增强没有解决这些问题，未为本轮测试临时堆叠特例规则。后续先改善互动边界，再以新场景验证，暂不推进动态示例选择。

本地主评测目录：`data/paimon-style-eval/2026-11-07T08-21-08-187Z/`，保留 manifest、完整回答、盲评表、manual-review 和解盲映射，均被 Git 忽略。记录的是本轮合成场景与公开语音，不含私人对话。结论：默认保持 off，可小范围对照试用 rules；当前不足以自动启用 examples。未推送、部署、修改服务器配置或重启。
