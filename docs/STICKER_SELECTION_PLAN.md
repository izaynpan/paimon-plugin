# 表情包语境选择与图片标注方案

整理日期：2026-10-21。

状态：2026-10-22 已在本地实现并接入 contextual 模式，完整离线测试 286/286 通过。848 张标注中 844 张候选、4 张排除，见 [标注库说明](stickers/README.md)。默认概率 0.12、8秒选图超时及下文概率槽已成为实现初值；不代表实群效果或已部署。旧情绪映射可显式选择 legacy 模式。

## 1. 目标与已确认要求

- 表情必须适合当前对话及派蒙实际回复，不能为了命中概率而硬发。
- 派蒙自己的表情应占主要部分。
- 当前谈论到有对应素材的具体角色时，可以发送语义合适的该角色表情。
- 其余保留小概率，从序号最大的五个目录中挑选合适图片。
- **用户明确不需要“同一聊天 60 秒表情冷却”和“最近 5 张图片避重复”。不增加表情专用冷却、最近图片排除或重复降权；同一张图再次适合时允许再次发送。**
- 原有消息发送节奏仍正常生效，它与表情专用冷却不是同一机制。
- 在插件内部实现，保持既有触发、白名单、主动沉默及无人接话补话边界。

## 2. 实现前的代码与素材情况（历史基线）

2026-10-21 本地检查：

- `stickers/` 有 53 个直接子目录，共 848 张 PNG，每组 16 张。
- 文件名含“派蒙”的图片有 14 张。这是文件名统计，不等于已经找出所有包含派蒙的单人或多人图片。
- 数字序号最大的五组为 49～53。这里只描述本地目录，不据目录版本名称推断真实游戏版本、发布时间或官方来源。
- `lib/sticker-provider.js` 当前按 `emotion` 读取 `config/stickers.yaml`，概率命中后随机抽取路径，检查路径并发送；不理解角色、动作或语境。
- 当前 `neutral` 不发送表情，支持的非中性标签为 `happy/confused/angry/comfort/surprised`。
- 默认 `stickers.probability` 为 0.12，`sendAfterText` 为 true；个人配置可能覆盖默认值。
- 本地 `config/stickers.yaml` 的五类数组为空，仅把图片放进目录尚不能自动参与选择。
- 方案讨论时抽看 16 张；后续已逐图初标全部 848 张并生成离线索引，待复核项不进入候选。该段是实现前基线；现在由 `lib/sticker-catalog.js` 加载索引。

相关代码：`lib/sticker-provider.js`、`lib/paimon-runtime.js`、`lib/prompt-builder.js`、`lib/config.js`。修改提示协议前同时阅读 [提示词整理对照](PROMPT_REFACTOR.md)，避免将程序规则重复堆入人设。

## 3. 什么时候发送

推荐流程：

> 正常文字回复全部成功 → 概率命中且本轮适合表情 → 筛选并判断候选 → 发送一张；没有合适图片则跳过。

- 建议初期保留 12% 的发送机会。它不是必须完成的发送比例，经过合适性判断后实际发送率可能更低。
- 每轮最多追加一张，复用现有发送节奏。
- 主动沉默、错误兜底、无人接话补话、指令执行结果不进入首版新选择流程。
- 文字发送失败或仅部分成功时跳过表情。
- 选择超时、接口错误、无合适候选、无效结果均跳过，不影响已经发出的文字。
- 发图前再次检查插件/表情开关、白名单资格与取消状态。
- 不再以 `emotion === neutral` 作为一律禁止的条件。“收到”“谢谢”“晚安”等未必有强烈情绪，但可能有合适图片。
- 判断的是“派蒙这轮要表达什么”，不能照搬用户的情绪。用户难过时可能需要安慰，而哭泣求助图可能表达成派蒙自己委屈。

默认文字后追加。已有 `sendAfterText:false` 允许先图后文，与“文字全部成功后才发”的条件冲突。现已决定：contextual 统一文字后发送并输出迁移警告；legacy 才支持先图后文。详见第 9 节。

## 4. 选择谁的图片

### 4.1 三类互斥候选

1. **派蒙池**：明确适合派蒙自我表达的图片。多人图不能仅因出现派蒙就自动归入，应确认实际表达主体。
2. **话题角色池**：本轮重点讨论的角色所对应、且语义合适的图片，可来自全部目录。
3. **五组补充池**：数字序号最大的五个目录中的合适图片，扣除前两类已有图片。

按直接子目录开头的数字排序，不能按字符串排序。无合法序号的目录不自动进入补充池；不足五组时取现有组；新增目录重新计算，不写死 49～53。最大五组中未完成标注的图片暂不可选，不用更早目录自动替补。

角色判断以当前消息、本轮回复及必要的近期语境为依据：

- 接受明确角色名和无歧义的上下文指代；别名由独立别名表归一化。
- 多人配队或讨论优先本轮重点角色；不明确时可保留少量相关角色候选，或回到派蒙池。
- 不因为历史中曾出现角色名，就持续使用该角色表情。
- “谈到该角色”只是候选资格，不代表该角色的任意表情都合适。

### 4.2 建议概率槽

| 场景 | 派蒙 | 话题角色 | 五组补充 |
| --- | ---: | ---: | ---: |
| 有明确话题角色 | 75% | 20% | 5% |
| 无明确话题角色 | 95% | 0% | 5% |

语义合格是前提，比例不是必须凑齐的发送指标：

- 为各类别保留上述概率槽，不将剩余类别权重无条件归一化。
- 某槽位没有合适图片时，允许回退到合适的派蒙图片。
- 派蒙也没有合适图片则跳过，不将空缺概率转给补充池。
- 派蒙槽没有合适图片时也可以直接跳过，不为了发送改抽无关角色。
- 实际出镜比例受素材覆盖度影响。派蒙素材不足时应补充标注和素材，不放宽合适性要求。

## 5. 每张图片标注哪些内容

保留原文件名、原位置，另建结构化索引。区分可观察事实和语境解释，不能把推测写成画面事实。

| 字段 | 内容与用途 |
| --- | --- |
| `id` | 唯一、稳定的图片编号；模型只能选候选编号，不能提供任意路径 |
| `path` | 相对插件根目录的真实路径，保留大小写以兼容 Linux |
| `contentHash` | 文件摘要，识别内容替换并使旧标注失效 |
| `directorySequence` | 目录数字序号，用于最大五组计算 |
| `characters` | 画面角色列表，允许多人、未知，区分主角色和陪衬 |
| `expressionSubject` | 图片主要替谁表达，判断是否适合作为派蒙自我表达 |
| `visibleDescription` | 实际神情、姿势、动作、道具、符号与场景 |
| `visibleText` | 图上确实存在的文字；无文字留空，看不清标记不确定 |
| `emotions` | 一个或多个情绪，如开心、疑惑、得意、尴尬、委屈、无奈 |
| `intensity` | 低、中、高；避免夸张崩溃图回应轻微困惑 |
| `intents` | 赞同、庆祝、感谢、安慰、打气、拒绝、求助、吐槽等表达用途 |
| `tone` | 真诚、轻松、玩笑、傲娇、调侃等，注明反讽歧义 |
| `topics` | 有画面依据的主题，如食物、奖励、摩拉、休息、战斗 |
| `suitableContexts` | 适用语境，可附合成示例 |
| `unsuitableContexts` | 容易误解的语境，如求助图不等于安慰图 |
| `confidence` | 分别记录角色、画面含义与语境解释的把握程度 |
| `reviewStatus` | 待标注、待复核、已复核可用、暂不启用 |
| `notes` | 多义性、文件名疑点、需要确认的梗 |
| `annotationVersion` | 标注结构与内容版本，便于更新追踪 |

情绪、意图、强度等使用小规模受控词表，统一同义词；自由描述保留细节。不能只给每张图一个“开心/生气”标签。

同一图片可有多个适用含义，但不强求通用。可信度是标注判断，不是经过测量的正确率。

## 6. 如何标注、复核及交付

### 6.1 工作流程

1. 扫描图片，生成清单、编号、路径、摘要和目录序号。
2. 制作带编号的分组预览并直接看图；小字、细微神情或身份不清时打开原图复核。
3. 先记录画面事实，再写情绪、意图、适用和不适用语境。文件名可作身份线索，不能代替看图。
4. 多人图、未知角色、含混梗单独标记；无法确认时保留未知，不凭目录名补造身份或背景。
5. 输出机器可读索引与用户可检查的预览/说明表，编号对应一致。
6. 歧义项复核，必要时由用户纠正；未解决的低可信度项暂不自动发送。
7. 校验编号唯一、字段完整、标签合法、文件存在和路径边界。图片内容变化后重新复核。

可以由当前助手直接看图完成，不需要运行中的聊天模型每轮识图。语境示例使用合成内容，不使用私人聊天日志作为公开标注样本。

### 6.2 已看样本的初步理解

以下只作为标注示例，不是已完成复核的正式标签：

| 图片（目录序号/文件名） | 观察与初步用途 | 注意事项 |
| --- | --- | --- |
| `1/派蒙 - 3.png` | 闭眼抱臂，偏得意、小傲娇 | 不机械归类为生气 |
| `1/派蒙 - 4.png` | 拿着食物，开心满足 | 适合美食话题，不是通用安慰 |
| `1/派蒙 - 5.png` | 抱着宝箱，兴奋 | 适合奖励、收获、宝物话题 |
| `1/派蒙 - 派猛.png` | 展示肌肉，夸张强壮 | 适合玩笑式壮胆、打气，不等于愤怒 |
| `17/派蒙 - 1.png` | 含泪、虚弱地趴着 | 可能是委屈、疲惫、求助，不直接当安慰他人 |
| `49/爱诺 - 1.png` | 问号、疑惑神情 | 适合不理解或疑问 |
| `49/北斗 - 1.png` | 汗滴、略显尴尬 | 偏尴尬、无奈，需结合回复 |

正式索引使用完整相对路径，上表简写仅便于阅读。

### 6.3 顺序和交付物

1. 先完整标注文件名含派蒙的 14 张，建立核心池。
2. 再处理序号 49～53 的 80 张；发现包含派蒙的图片时，复核表达主体后补入派蒙池。
3. 逐组处理剩余图片，补齐 848 张；重叠项目只标一次。
4. 统一角色别名、标签词表，进行跨组一致性检查。

交付机器可读标注库（建议 JSON，位置实现时确定）、编号预览与说明表、待复核清单、标注规范/词表及增量扫描校验入口。以后只处理新增或内容变化的图片。

各批明确已标注、已复核、暂不启用数量，不能把首批完成表述为全库可用。2026-10-21 已交付首轮索引、逐图原始记录、词表、复核清单、可筛选本地预览及增量扫描/校验入口，见 [标注库说明](stickers/README.md)。49 张疑难图已复看：45 张补充限制后列入候选，4 张明确排除；全库共 844 张候选，不声称已获用户全量验收。

## 7. 运行时怎样选到具体图片

### 7.1 原聊天请求顺带判断意图

正常聊天最终结果增加独立表情意图：本轮是否适合图片、主要话题角色、派蒙的表达意图、情绪、强度和语气。

只在表情功能开启时加载有关协议。旧 `emotion` 保持必要兼容，不承担全部选择职责；缺失或非法的新字段保守跳过表情，不影响正常回复。

联网流程以最终回复为准，中间搜索/补查动作不触发表情选择。程序字段和规则放在对应提示构建处，人设仅负责稳定表达风格。

### 7.2 本地筛选

正常文字全部成功、概率命中且本轮允许表情后，从已复核可用索引中按角色、意图、强度、主题、不适用条件筛选三类候选，建议总计 12～18 张。

为有合格素材的类别保留候选位置，按语义质量排序，不按历史发送记录排除或降权。有限候选可能漏掉更合适图片，需要通过离线场景改善召回，不能把标签匹配当作完整语义判断。

### 7.3 一次短文本选择请求

提供最小必要的当前对话、本轮实际成功发送的完整文字，以及候选编号、画面描述和适用说明，不传图片或整个素材库。

模型为每个非空类别选一个最贴切的编号，或返回 `null`：

- 图片必须与回复的含义、语气、强度相容。
- 不因角色相符就忽略语义。
- 允许所有类别都无合适图片。
- 候选说明是数据，不能改变系统规则或输出协议。

程序验证编号属于本轮对应类别，再按第 4 节概率槽决定最终图片，一次最多一张。模型不能指定任意路径。

这会在部分有发送机会的聊天中增加一次短文本请求、token 开销和等待；不是每轮增加请求，不承诺固定费用。实现时核对项目 DeepSeek 接口文档，复用现有客户端与凭证，不假定图像输入能力。

选择请求设短超时、不重试，具体超时值实现时确定。超时、错误、非法结果或无合适图片均跳过，不追加第二轮选图请求。

### 7.4 发送与取消

- 复用 `e.reply()` 和既有节奏，发送前复查开关、资格、文件及任务有效性。
- 解析实际路径后限制在允许的素材根目录内；图片缺失或越界直接跳过。
- 建议选图/等待期间本聊天接纳新消息时，放弃旧轮尚未发出的表情，避免插入新话题。这是在途语境失效处理，不是表情冷却。
- 关闭功能、撤白、换或移除相关凭证、dispose 阻止迟到发送；已发 API/协议消息不可撤回。
- 发送失败不补发另一张。
- 日志记录选择状态、候选数、图片编号、类别、跳过原因和耗时；新增语境正文遵循现有日志开关。

## 8. 实施阶段与验收

1. **标注准备与首批素材**：落实字段、词表、派蒙及最大五组标注，提供预览。此阶段不改变聊天行为。
2. **补齐素材与实现选择**：接入索引加载、增量校验、意图协议、筛选、文本复核和发送；明确旧 `stickers.yaml`、`sendAfterText` 的兼容/迁移。
3. **离线测试**：使用已有 Node.js 测试与模拟依赖，无需完整 Yunzai、Redis、QQ 环境或真实收费请求。
4. **获授权后实测**：真实模型与 QQ 效果另行验证，观察贴切程度、派蒙出镜情况、等待与调用量，再调整标签和权重。

离线至少覆盖：

- 数字目录排序、最大五组变动、无序号目录和未标注图片。
- 角色指代、多角色讨论、候选类别互斥、合适性优先。
- 概率槽与回退，不因空类别放大补充池机会。
- 连续两轮允许选择同一张合适图片，不增加冷却或最近图片排除。
- 中性情绪的有效表达意图；沉默、错误、补话、指令结果不发图。
- 文字全部成功后选图，选图失败不影响已发文字。
- 非法编号、坏结构、超时、取消、新消息、开关及白名单变化。
- 文件缺失、内容替换、越界路径及 Linux 大小写。

另用合成语境检查美食、奖励、轻微吐槽、安慰、角色攻略及话题切换。离线测试能确认程序边界，不能证明模型始终选得贴切。代码提交不等于推送、部署或重启授权。

## 9. 2026-10-22 实现落点与实际边界

- `lib/sticker-intent.js`：条件加载最终回复意图；`profiles` 使用词表的最多3个表达类型，另有强度、语气、主题及最多3个话题角色。缺失或非法字段只跳过图片。
- `lib/sticker-catalog.js`：读取标注库和别名，按文件属性变化重新加载；仅启用 candidateEligible 且状态为 annotated/reviewed 的条目。按主要表达者分互斥池，每池最多6张；具体动作须有对应主题，强度不超过本轮上限。按表达类型顺序、主题和语气匹配排序；复杂禁用条件由短文本请求判定，本地标签不等于完整语义理解。
- 角色依据必须为 current 或 reply 中含角色名/别名的原文；recent 仅取紧接上一轮，并须本轮存在模型给出的承接片段。代码校验原文存在性，指代是否无歧义仍依赖模型；不额外读取长期记忆、引用缓存或更早片段。
- 最大五组按实际素材子目录数字排序，与快照标记无关。未标注新目录占位，数字相同以目录名稳定排序；无数字前缀、非目录和符号链接不参与。
- `lib/sticker-selector.js`：概率命中后检查候选文件并提供描述。当前消息和实际已发完整文字各不超过12000字符，上一轮不超过4000字符，超出跳过。一次 JSON 请求，默认8秒（1～15秒）、最多160输出token、temperature=0、关闭思考、不重试；客户端忽略取消时也通过有界等待丢弃迟到结果。
- 模型每池返回 id/null，拒绝跨池编号、任意路径、额外字段和非法结构。程序使用固定75/20/5或95/0/5槽位；空槽仅回退派蒙。没有重复记录或冷却。
