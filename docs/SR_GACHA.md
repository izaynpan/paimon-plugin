# 星铁扫码更新抽卡记录

2026-10-23 实现于 paimon-plugin；本地测试完成后仍需更新服务器代码并重启才能生效。

## 原因与接入

只读核对服务器 genshin `0290a17`、xiaoyao-cvs-plugin `e7ab3e8`：

- 框架将 `*更新抽卡记录` 规范化为 `#星铁更新抽卡记录`。
- 逍遥 `apps/user.js` 的 `gclog` 规则只匹配 `#更新抽卡记录` 等原神入口；凭证请求和链接中的 `game_biz`、区服及接口也写死为原神。直接扩展正则会选错游戏/账号。
- genshin 的 `apps/gcLog.js` 支持星铁链接导入、记录查询/统计，但没有扫码凭证更新入口。
- 绝区零通过当前游戏 UID 的 `getUidData` 找到米游社 ID，再在发送者的逍遥凭证文件里按 `stuid` 匹配。本功能沿用这一账号匹配思路。

新增 `apps/sr-gacha.js`，priority=50，仅接管 `*更新抽卡记录` / `*刷新抽卡记录` 及对应规范化星铁指令；返回 true 消费命令。原神、绝区零、导出、手动链接和普通记录查询仍走原功能。不会修改第三方源码或全局 prototype。

## 使用与配置

先私聊 `#扫码登录`，选择要更新的已登录星铁 UID，再发送 `*更新抽卡记录`。完成后用 `*抽卡记录`、`*全部记录` 或原统计指令查询。

```yaml
srGacha:
  enabled: true
  cooldownMs: 300000
```

默认开启；独立于聊天 enabled、聊天群白名单、commandRouting 和 DeepSeek Key，不调用模型。框架自身的黑名单、群插件启停等过滤照常生效。每次命令重新读取配置；修改配置作用于下次命令，不取消已开始的更新。首次安装 JS 需要重启。关闭该开关即可停用此入口。

当前支持星铁国服官服及 B 服；其他区服保留原抽卡链接导入方式。需要已有的 genshin 和逍遥插件；不依赖 ZZZ-Plugin。

## 数据与边界

- 只使用事件发送者 `e.user.getUid('sr')` 当前账号，要求同一用户的 `getUidData(uid,'sr')` 为 CK 类型。不会使用 @对象、原神 UID、公共 Cookie 或自动切换其他账号。
- 只读取该发送者的 `xiaoyao-cvs-plugin/data/yaml/<QQ>.yaml`，按当前 UID 对应的米游社 ID 匹配 stuid，支持旧单条和多条格式。没有凭证时提示扫码，不重新实现登录。
- 在独立适配实例上复用逍遥的 DS/请求头方法，跳过会按原神 UID 选凭证的构造函数；请求固定国服官方 `genAuthKey`，使用 `hkrpg_cn`。接口和签名以后变化时仍可能需要更新适配。
- 凭证仅在本次调用内使用，不加入原事件、模型上下文、回复或派蒙日志；不额外保存 authkey，不修改扫码凭证。请求拒绝重定向、单次超时15秒，异常不转发 URL/服务端原文。
- 用 genshin 实例的六类卡池、`getAllLog` 分页/增量判断、`mergeGachaData`、`readJson` / `writeJson` 保存数据。仅该实例的请求方法替换为有限时、脱敏错误并校验记录 UID 的星铁请求；普通池及联动池分别请求对应接口。
- 文件仍是 `data/srJson/<QQ>/<UID>/<卡池>.json`，原查询、统计、导出可继续使用。空池不会阻断后续池；全量模式沿用原合并逻辑，全部成功后关闭一次性全量标志。
- 中途失败停止后续池，保留先前成功池；失败池不写入本次未完整取得的数据，回复明确未全部成功。重试沿用已有记录去重。文件写入沿用原插件实现，不提供跨池事务。
- 同一 QQ 在多个群/多个 Bot 共用内存运行锁和冷却；发起接口更新后默认冷却5分钟，可配置30秒～1小时。与原神/绝区零冷却分开，重启后清空。这里只约束本入口；不要在更新期间对相同记录同时执行原插件手动导入。
