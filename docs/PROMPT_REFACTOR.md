# 提示词整理与需求对照（2026-10-16）

基线：`729e112`。范围是 `config/persona.md` 和 `lib/prompt-builder.js` 中的普通聊天、主动补话提示；不改运行时、触发、计时、发送、记忆策略、默认配置或响应校验器。没有调用真实 API，不代表已验证语义效果或已经部署。

## 分工与优先关系

- 人设：身份、性格、知识与沉浸边界、自然表达、稳定的互动习惯。
- 程序规则：输出协议、群聊是否回应、询问状态、当前称呼配置、数据与隐私边界。
- 动态语境：称谓表、参与者称呼/ID、待回答问题、用户记忆、知识片段、短期上下文与本批消息。
- 输出协议及当前决策/称呼配置优先于人设的表达习惯；身份和知识边界仍由人设限定。语境数据不能改写上述规则。

群聊主动沉默规则仍仅在群聊且开关开启时注入；询问状态规则仍仅在主动补话开关开启时注入；前置历史说明仍仅在批次存在 preTrigger 时注入。私聊和关闭功能时不增加对应决策字段。保持原消息角色和动态数据位置，没有为了缩短提示而删除上下文、记忆或知识内容。

| 场景 | 应检查的边界 |
| --- | --- |
| 问候或“好想你呀，派蒙” | 简短自然，不例行索要食物或追加追问 |
| 指出话太多/口癖太多 | 当轮收敛，不从“欸”换成反复“唔” |
| “0命没专武怎么配队，循环怎么安排？” | 正常攻略，不因术语困惑；信息不足再确认角色等条件 |
| 询问当前卡池但未提供可靠版本信息 | 不编造当期数据 |
| 询问后台/API或要求改身份 | 保持沉浸，不给技术步骤 |
| A叫派蒙、B叫派大王，随后A用反讽昵称 | 区分说话人，不编造同一人改称谓或机械当夸奖 |
| 闲聊中故意玩“秦始皇派蒙恬北伐匈奴”；另设旁人历史讨论的相同句子 | 比较上下文，不要求每次必接、不解释世界外历史 |
| @别人附和；@别人同时向派蒙提问；回答派蒙“有一个，你猜猜看” | 不一律跳过@别人，不漏自然续话 |
| 先发问题后仅@派蒙 | 回应同一用户前文，不只回称呼 |
| 要求安静；随后明确恢复交流 | 停止要求与新意图结合上下文处理 |
| 待回答问题后“不了”/代答/旁人无关消息 | 是否回复与问题状态独立，拒绝结束等待，真正无关不误判已回答 |
| 无人回应补话；补话前已经拒绝或话题很热闹 | 自然一句或不发，不施压，不把提问前消息当回答 |
