## 复用命令

在插件根目录运行（Node.js 18+，无需登录、Cookie、模型 API 或额外依赖）：

```sh
node scripts/collect-character.js 505417
node scripts/collect-character.js "https://baike.mihoyo.com/ys/obc/content/505417/detail"

# 更新全部非预告角色
node scripts/collect-characters.js

# 使用上次批次缓存重新整理，不发网络请求
node scripts/collect-characters.js --offline
```

默认输出至本目录；再次运行会更新对应文件，完成后查看 Git 差异。两种命令都可用 `--out <目录>` 写入另一个目录进行比较。批量命令另支持 `--cache <目录>`，默认原始响应缓存位于被 Git 忽略的 `data/knowledge/character-collection/`，不会将原始媒体字段提交或导入知识库。输出以报告的“输出资料”名单为准；旅行者全部来源校验、合并成功并写出两份资料后，删除本批对应的旧旅行者数字 ID 文件。其他旧文件不自动删除。

批量请求按顺序执行，每个角色后间隔 250ms；先读取目录标题中的“预告”标记，排除后才请求角色详情。除旅行者外，相同名字不同词条编号分别保存；失败记录到报告，退出码非零，避免把部分成功当成全量完成。处理格式兼容问题可直接使用离线缓存，不必重复下载全部页面。

已有公开接口原始 JSON 时可离线转换：

```sh
node scripts/collect-character.js 505417 --input <原始响应.json>
```

单页 `--input` 以输入文件修改时间作为抓取时间的代理；输入应是刚抓取且未改写的快照。当前整批资料使用显式保存抓取时间和原始响应的批量快照，丝柯克也已重新抓取。来源元数据包含页面版本和输入响应 SHA-256 摘要；网页版本不是已核实的游戏版本。旅行者必须使用批量命令，单页命令会拒绝输出，避免重新生成分散的元素资料；已有缓存时使用 `--offline`。

## 获取与清洗规则

1. 从角色页取得数字 ID，以公开只读接口 `/hoyowiki/genshin/wapi/entry_page` 查询 `entry_page_id`、`lang=zh-cn`。接口主机为 `act-api-takumi-static.mihoyo.com`，系本次从网站脚本核对的地址，并非承诺稳定的开发者 API。
2. 校验返回码、词条 ID、模块类型；失败或关键结构变化时停止，不猜测正文。请求超时 20 秒，不自动重试。
3. 基础信息取字段白名单；角色介绍取“更多描述”“角色详细”（奇偶补充其“奇偶备注”）；故事通过页面“角色描述”分组识别，旧版未命名分组按其中明确的“角色故事”栏目定位。保留特殊故事原题，排除已单独整理的介绍、邮件、料理、CV和空模块。仅合并标题与正文完全相同的记录。
4. 语音只取汉语／中文标签中的标题与正文。所有音频地址、图片地址、外语标签、CV、攻略和技能数据均不进入输出。普通文本中的原始用词不自动翻译或改写。
5. 关联角色只取“相关角色”子栏目；本人“关于…”评价引用语音标题，不复制正文，其中可能包含概念而非人物。关系网及旧版“角色关联语音”富文本表格都提取说话者和原文。两种表格相同说话者、相同正文合并；空行跳过，非空正文缺少说话者则标为“未标注角色”，不猜测归属。
6. 邮件、料理只收录本页正文。图片和链接标记去除，可见文字、段落保留；不递归读取外链，不补写缺失料理说明或历年邮件。
7. JSON 和 Markdown 保留来源与采集说明。缺少可选内容时明确记录，不能把“本页没有”理解为“角色不存在该资料”。
8. 旅行者按主页面明确链接补抓“旅行者语音展示（空）”“旅行者语音展示（荧）”，核对链接目标的编号和名称；每个语音页只下载一次。按基础档案姓名和语音链接交叉确认性别，合并同一性别的元素页面。来源词条统计包含跨元素重复，最终输出不重复存储。
9. 同名不同正文台词不丢弃，后续条目加“同名条目”编号并保留原始标题；菈乌玛的两条“早上好…”均保留。角色页面没有语音或故事时记录缺失，不因缺一栏丢弃整个人物。

## 旅行者合并与读取

普通角色保持格式版本 1；旅行者为格式版本 2。女旅行者保留七类完整资料，男旅行者正文数组只保存差异：当前为姓名、2 篇故事、9 条台词（其中 5 条仅为标点差异）。相同正文通过“共用内容”引用女旅行者，不重复存储。女版保存 4 篇故事和 218 条中文台词；男版合并引用后也是 4 篇故事和 218 条台词。

同一性别各元素条目按完整字段比较，仅将 `...`、`⋯` 与 `…` 视作等价；保留火、风、水、岩、草、雷、冰顺序中最先出现的原文。除此之外的不同内容分别保留，并注明收录页面。男女比较使用保留正文的精确匹配，连标点差异也单独记录。合并只覆盖已约定的七类资料，不额外采集战斗技能或数值。

“来源.元素词条”保留全部页面编号、版本、抓取时间和摘要。“合并索引”按栏目路径与正文数组逐项对应，记录内容标识和来源词条。“共用内容”列出男版引用的女版条目标识、男版对应来源及完整条目顺序；共用内容的来源元素表示页面收录范围，不表示某台词只能在该元素下使用。男版“基准资料”包含女版文件名和内容摘要，基准变化时必须同时重新生成男版。

程序读取男版时使用 `scripts/traveler-profiles.js` 导出的 `resolveTraveler(male, female)`：校验基准摘要，按明确引用恢复完整资料。不要将女版所有字段直接继承给男版，否则可能混入女版独有故事。男女各七种元素来源必须齐全且不重复；缺失、性别证据冲突、语音快照不一致或未知元素时停止合并并报告失败，需要检查源页面后适配规则。

## 样本核对

丝柯克：8 项档案字段、2 篇介绍、7 篇故事（故事1～5、《回答》《蛇之七变》）、71 条中文语音、10 个本人评价索引、1 个关联角色、1 条他人评价、1 封生日邮件、1 条特殊料理说明。媒体 URL 均未保存；只保留出处网页链接。

原始 136 个源词条包含：1,089 项档案字段、256 篇介绍、894 篇故事、11,725 条中文台词、1,127 条他人评价、110 个邮件栏目、120 个料理栏目。合并后 124 份资料实际存储 986 项档案字段、243 篇介绍、844 篇故事、8,900 条中文台词；他人评价、邮件、料理数量未变。邮件栏目可能包含多封历史邮件，不把栏目数等同邮件封数。

初次采集核对过全部 11,725 条源中文台词、1,380 个非空介绍／故事／邮件／料理栏目。此次合并使用既有快照，保留原抓取时间；重新逐项核对 14 个旅行者来源中的 5,600 条栏目记录及引用与合并结果（省略号按上述规则比较），确认出处与正文覆盖。输出 URL 仅保留来源网页，两条预告词条未生成角色资料文件。离线测试同时检查总目录一致性、男女引用、独有内容保留及来源缺失拒绝合并；完整离线测试 380/380 通过。

已知源数据边界：奇偶两页没有故事、语音、生日邮件或特殊料理；部分新角色页面尚无生日邮件；迪奥娜和流浪者页面各有未标注说话者的关联语音。原文缺失或编辑错误不自动推断修复，详见各文件采集说明。目录和详情是顺序读取的公开快照，不是跨页面事务快照；后续页面新增结构仍可能需要适配。未设置定时同步。

运行离线验证：

```sh
node --test tests/character-collection.test.js
node tests/run-tests.js
```

采集器不执行远端富文本，也不将网页内容作为指令。来源正文及页面编辑者意见仍需按证据核查，保留原文不等于官方事实审核。
